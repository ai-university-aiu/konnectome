PART FIVE - OTHER CONTEXT YOU SHOULD KNOW (SHARP EDGES AND HONEST NON-CLOSURES)


• THE NEW HONEST NON-CLOSURE FROM SLICE 13 (Observation-3 in the ledger). konnectome mints assertion and retraction records that are content-addressed, schema-valid, and semantically valid, carrying its PUBLIC source identity and its evidence grade - but it does not itself produce the Ed25519 SIGNATURE the provenance model specifies. The signature needs a PRIVATE key, and a private key is a secret barred from konnectome's code by Specification Constraint 3 (and Section A5.5's no-secret rule), so signing is a deployment-time act. The signature is optional to the schema and excluded from content-addressed identity, so the records validate and reproduce without it; a strict consumer, following the standard's store discipline, would quarantine them as unsigned until the deployment signature is applied. It is LOGGED, NOT ROUTED: not a data-structure gap (the standard carries the signature) and not a wall konnectome hit by building (the cognitive act is fully realized at the record level). It is recorded as a candidate FUTURE consideration only: were konnectome ever to need to SHARE cryptographically VERIFIABLE assertions across minds, a signing-and-verification primitive in the reused PrologAI causal_core library would be where that finding routes - discovered by building, if and when the need is real. Verified this session: causal_core content-addresses but neither signs nor verifies, and the installed SWI-Prolog (version 9.0.4) has no ed25519 curve in library(crypto).

• THE PACK-NAME SHADOWING HAZARD (still true; verified again this session). A konnectome pack may not share a name with ANY module file under PrologAI's packs - the library path gives PrologAI's directories priority, so a clashing konnectome pack silently loads the wrong module. Before creating any pack, check the candidate name against every PrologAI module filename. I checked self_provenance (and several alternatives) against PrologAI's packs and confirmed it was clear.
