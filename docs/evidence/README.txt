THE EVIDENCE DIRECTORY

WHAT THIS DIRECTORY IS

This directory holds konnectome's records of PUBLISHED LITERATURE SEARCHED FROM OUTSIDE THE CORPUS, under the Twenty-Second Commandment, THE JUDGEMENT-CALL PROTOCOL.

It exists because the corpus is large and it is not everything, it has a date on it, and the science moves. When a flagged judgement call is worked and the north-star directory turns out to be silent or incomplete on the question, the protocol says to search the published literature - and what that search finds has to live somewhere.

It lives here, and it does not live in docs/neuroscience/ .


THE ONE RULE THAT MATTERS, STATED FIRST

EVERY DOCUMENT IN THIS DIRECTORY IS OUTRANKED BY THE NORTH STAR.

Where an evidence record and a north-star document disagree, THE CORPUS LEADS, and the RECORD is the thing annotated. Never the corpus.

The reason is this build's own oldest fear, at the scale of a document rather than a number. konnectome's name for its worst failure mode is AN INVENTED VALUE THAT HAS LEARNED TO CITE - a thing the builder chose, left where a reader will take it for the source's.

A search result filed inside the corpus is exactly that failure, one level up. It would wear the north star's authority for every session afterwards, and no later reader could tell it apart from the corpus's own text by looking at it. So it is kept apart, and this paragraph is the first thing in the directory so that nobody has to work the ranking out.


WHAT A RECORD MUST CARRY

Every record in this directory carries, on its own face:

• THE QUESTION it was searching to answer, and the flagged judgement call it belongs to - a decision number, an observation number, or a named stopgap.

• THE QUERY that was actually run, in the words it was run in, so that somebody can run it again.

• THE DATE it was run, because a literature search is a measurement of a literature at a moment.

• THE SOURCES, with their addresses, and enough of each one to see what it actually said rather than what it was summarised as saying.

• WHAT IT SETTLES.

• WHAT IT DOES NOT SETTLE, which is usually the longer list.

• WHETHER A CORPUS GAP WAS FOUND, and if so, what the gap is - because that is what the update run promotes.


A NEGATIVE RESULT IS A RESULT

A record that says "this was searched for, in these words, on this date, and it is not there" is as valuable as one that finds a number, and it is written with the same care.

It is the finding that stops the next session searching the same ground again, and it converts a refusal that has only survived a READING into a refusal that has survived a SEARCH. Those are different objects and the ledger should say which one it holds.


HOW A RECORD REACHES THE CORPUS

Only through the CORPUS UPDATE RUN of the Twenty-Second Commandment, which happens EVERY TENTH HAND-OFF and is its own act, never done inside a slice.

The run is ADDITIVE ONLY. It never alters or deletes anything the corpus already says. Every block it adds carries its provenance on its face - that konnectome added it, the date, the evidence record it came from, and the sources - so a reader can tell at a glance which sentences are the corpus's and which are this build's.

And a promoted block still does not outrank the corpus's own text. Promotion changes where a finding LIVES. It does not change what it is.


THE NAMING CONVENTION

Records are numbered in the order they are written, as 01_, 02_ and so on, with a whole-words snake_case subject and a version suffix. The number is the order of writing and carries no ranking.

Superseded versions of a record move to docs/archive/ under the Eleventh Commandment, exactly as every other versioned document in this repository does.
